# FT-02 Manajemen Data Master (Pegawai, Kategori, dan Pengaturan Unit)

Sumber PRD: Bagian 4 (Hak Akses Admin), BL-01 (Exceptions), FT-02, Bagian 11 (Entitas User, WorkCategory, UnitSetting), dan Keputusan Tahap 1 (3A)

## Tujuan
Admin dapat menambah, mengubah, dan menonaktifkan data pegawai beserta peran akunnya, mengelola master kategori pekerjaan, serta memperbarui identitas unit kerja untuk kop laporan.

## Alur
1. Admin membuka menu **Data Master** pada bilah navigasi atas.
2. Admin memilih salah satu kelompok data: **Pegawai**, **Kategori Pekerjaan**, atau **Pengaturan Unit**.
3. Untuk **Pegawai** atau **Kategori Pekerjaan**:
   - Admin melihat tabel/daftar seluruh data beserta status Aktif/Nonaktif.
   - Admin menekan tombol **Tambah Pegawai** atau **Tambah Kategori**, mengisi formulir, lalu menekan **Simpan**.
   - Untuk mengubah data, Admin menekan tombol **Ubah** pada baris terkait, memperbarui isian, lalu menekan **Simpan**.
   - Untuk menonaktifkan atau mengaktifkan kembali, Admin menekan tombol **Nonaktifkan** atau **Aktifkan** pada baris terkait (khusus akun sendiri yang sedang login, tombol Nonaktifkan dinonaktifkan).
4. Untuk **Pengaturan Unit**:
   - Admin mengubah Nama Unit Kerja, Nama Pimpinan, atau NIP Pimpinan, lalu menekan **Simpan Pengaturan**.
5. Seluruh perubahan disimpan ke `localStorage` dan langsung tercermin pada daftar pengguna, pilihan kategori, serta kop laporan.

## Data
- `ROLE_LABELS`
- `VALIDATION_MESSAGES` (`forbiddenAction`)
- `AppStorageState.users` (`UserEntity[]`)
- `AppStorageState.categories` (`WorkCategoryEntity[]`)
- `AppStorageState.tasks` (`WorkTaskEntity[]` untuk pengecekan relasi aktif)
- `AppStorageState.unitSetting` (`UnitSettingEntity`)

## Aturan dan rumus
- **Otorisasi (BL-01):** Semua fungsi mutasi master data memeriksa `assertAdminRole(actorUser)`. Jika bukan `ADMIN`, fungsi menolak dengan status `403`.
- **Anti-duplikasi Pegawai:** `nip_or_employee_code` (setelah `trim`, tidak peka huruf besar/kecil) dan `email_or_username` (setelah `trim`, tidak peka huruf besar/kecil) harus unik di seluruh daftar pengguna.
- **Anti-duplikasi Kategori:** `category_name` (setelah `trim`, tidak peka huruf besar/kecil) harus unik di seluruh daftar kategori.
- **Perlindungan akun aktif & riwayat historis (BL-01 Exceptions & Bagian 11):**
  - Admin tidak dapat menonaktifkan akun miliknya sendiri yang sedang aktif (`targetUser.id === actorUser.id`).
  - Data pegawai maupun kategori tidak dihapus permanen agar riwayat tugas historis tetap utuh; pengelolaan status memakai mekanisme aktif/nonaktif (`is_active`).
  - Pegawai berstatus `is_active = false` tidak dapat masuk ke aplikasi, tetapi pekerjaan lamanya tetap dihitung dalam laporan historis.
- **Kata sandi pegawai:** Wajib diisi minimal 6 karakter saat membuat pegawai baru; saat mengubah data pegawai, kolom kata sandi boleh dikosongkan jika tidak ingin mengganti kata sandi lama.

## Input dan validasi
### 1. Formulir Pegawai
- **NIP / Kode Pegawai** (`name="nip_or_employee_code"`, wajib): tidak boleh kosong dan tidak boleh sama dengan pegawai lain. Contoh error: `"Masukkan NIP atau kode pegawai yang belum digunakan (contoh: 199501012022031001)."`
- **Nama Lengkap** (`name="full_name"`, wajib): tidak boleh kosong. Contoh error: `"Masukkan nama lengkap pegawai (contoh: Ahmad Fauzi)."`
- **Jabatan** (`name="position"`, wajib): tidak boleh kosong. Contoh error: `"Masukkan jabatan pegawai (contoh: Analis Data)."`
- **Email / Username** (`name="email_or_username"`, wajib): tidak boleh kosong, tidak mengandung spasi di tengah, dan unik. Contoh error: `"Masukkan username atau email tanpa spasi (contoh: ahmad.fauzi)."`
- **Kata Sandi** (`name="password"`, wajib saat tambah baru, opsional saat ubah): minimal 6 karakter jika diisi. Contoh error: `"Kata sandi minimal 6 karakter (contoh: sandi123)."`
- **Peran** (`name="role"`, wajib): salah satu dari `ADMIN`, `PEGAWAI`, `PIMPINAN`.

### 2. Formulir Kategori Pekerjaan
- **Nama Kategori** (`name="category_name"`, wajib): tidak boleh kosong dan tidak boleh sama dengan kategori lain. Contoh error: `"Masukkan nama kategori yang unik (contoh: Pengawasan Lapangan)."`
- **Keterangan** (`name="description"`, opsional): teks singkat penjelasan kategori.

### 3. Formulir Pengaturan Unit
- **Nama Unit Kerja** (`name="unit_name"`, wajib): tidak boleh kosong. Contoh error: `"Masukkan nama unit kerja untuk kop laporan (contoh: Subbagian Data)."`
- **Nama Pimpinan** (`name="leader_name"`, wajib): tidak boleh kosong. Contoh error: `"Masukkan nama lengkap pimpinan penanda tangan laporan."`
- **NIP / ID Pimpinan** (`name="leader_nip"`, wajib): tidak boleh kosong. Contoh error: `"Masukkan NIP atau kode pimpinan (contoh: 197504122000031002)."`

Semua input dibersihkan spasi awal/akhir (`trim`) sebelum divalidasi, dan saat ada error fokus berpindah ke kolom error pertama.

## Tampilan dan teks
- Judul bagian: **Manajemen Data Master**
- Deskripsi singkat: **Kelola daftar pegawai, kategori pekerjaan, dan identitas unit kerja.**
- Sub-menu tab: **Pegawai**, **Kategori**, **Pengaturan Unit**
- Formulir tambah dan ubah untuk **Pegawai** dan **Kategori** dibuka dalam dialog modal di atas daftar data.
- Status pada tabel memakai badge `rounded-full` dengan ikon:
  - Aktif: `bg-emerald-50 text-emerald-800`
  - Nonaktif: `bg-neutral-100 text-neutral-800`
- Tombol aksi utama: **Tambah Pegawai**, **Tambah Kategori**, **Simpan**, dan **Simpan Pengaturan**.
- Pesan berhasil tampil singkat saat data tersimpan.

## Kasus uji
| ID | Input | Hasil yang diharapkan | Sumber |
| :--- | :--- | :--- | :--- |
| FT02-H1 | Admin menambah pegawai baru dengan NIP dan username unik | Pegawai baru tersimpan dengan `is_active = true` dan muncul di daftar pegawai. | PRD FT-02 |
| FT02-E1 | Admin menambah pegawai dengan `email_or_username` atau `nip_or_employee_code` yang sudah ada | Penyimpanan ditolak dan muncul pesan error duplikat pada kolom terkait. | PRD Bagian 11 |
| FT02-E2 | Admin mencoba menonaktifkan akun dirinya sendiri (`targetUser.id === actorUser.id`) | Aksi ditolak dan status aktif Admin tidak berubah. | PRD BL-01 |
| FT02-H2 | Admin menambah kategori baru `"Evaluasi Anggaran"` | Kategori baru tersimpan dan dapat dipakai pada data pekerjaan. | PRD FT-02 |
| FT02-E3 | Admin menambah kategori dengan nama sama beda huruf besar/kecil (`"pengolahan data"`) | Penyimpanan ditolak karena nama kategori sudah ada. | PRD Bagian 11 |
| FT02-E4 | Pengguna dengan peran `PEGAWAI` atau `PIMPINAN` memanggil fungsi mutasi master data | Fungsi menolak dengan status `403` dan data tidak berubah. | PRD BL-01 |
| FT02-B1 | Admin mengubah Pengaturan Unit dengan spasi di awal/akhir nama unit | Spasi dibersihkan, `unitSetting` diperbarui, dan tersimpan di `localStorage`. | Tambahan |

## Di luar lingkup
- Penghapusan permanen (*hard delete*) data pegawai atau kategori yang berpotensi merusak laporan historis.
- Reset kata sandi lewat email atau verifikasi OTP.

Tidak ada. Pilihan tampilan 1A (tiga sub-tab dengan formulir dialog modal) telah disetujui pengguna.
