# FT-08 Detail Pekerjaan & Riwayat Perubahan

Sumber PRD: BL-01, BL-02, BL-03, BL-05, FT-08, AC-07, Bagian 11 (`WorkTask` & `TaskAuditLog`)

## Tujuan
Admin, Pegawai, dan Pimpinan dapat melihat seluruh rincian atribut suatu pekerjaan, membuka tautan bukti dokumentasi di tab baru, serta menelusuri lini masa riwayat perubahan status dari waktu ke waktu.

## Alur
1. Pengguna menekan judul pekerjaan atau tombol **Detail** pada salah satu baris di **Daftar Pekerjaan Unit**, **Tugas Saya**, maupun tabel **Pekerjaan Belum Selesai & Terlambat** di **Ringkasan Unit**.
2. Sistem memeriksa izin baca (BL-01): untuk peran `PEGAWAI`, hanya mengizinkan tugas dengan `task.employee_id === currentUser.id`.
3. Sistem mengambil seluruh atribut tugas, status keterlambatan (`computeTaskDeadlineStatus`), serta menyaring catatan `TaskAuditLog` milik tugas tersebut.
4. Modal detail menampilkan rincian lengkap tugas, tombol **Buka Tautan** (`target="_blank" rel="noopener"`) jika link tersedia, dan lini masa riwayat perubahan.
5. Pengguna menekan tombol tutup atau tombol `Escape` untuk kembali ke posisi daftar sebelumnya.

## Data
- `AppStorageState.tasks` (`WorkTaskEntity`)
- `AppStorageState.auditLogs` (`TaskAuditLogEntity[]`)
- `AppStorageState.users` (`UserEntity[]`)
- `AppStorageState.categories` (`WorkCategoryEntity[]`)
- `formatDateId`, `formatDateTimeId` dari `src/lib/format.ts`
- `computeTaskDeadlineStatus` dari `src/lib/overdue.ts`

## Aturan dan rumus
- **Otorisasi baca (BL-01):**
  - `ADMIN` dan `PIMPINAN` boleh melihat detail semua tugas unit.
  - `PEGAWAI` hanya boleh melihat detail tugas dengan `task.employee_id === actorUser.id`; jika mencoba membaca detail tugas pegawai lain, fungsi mengembalikan `{ ok: false, statusCode: 403 }`.
- **Pemetaan label riwayat (`action_type`):**
  - `CREATED` -> `"Pekerjaan dicatat"`
  - `STATUS_CHANGED` -> `"Perubahan status"`
  - `LINK_UPDATED` -> `"Tautan dokumentasi diperbarui"`
  - `DETAILS_UPDATED` -> `"Rincian pekerjaan diperbarui"`
- **Urutan lini masa:** Catatan riwayat diurutkan berdasarkan `created_at` dari waktu terbaru ke terlama (atau jika belum ada catatan log untuk tugas tertentu, tampilkan satu keterangan `"Belum ada catatan riwayat perubahan."`).
- **Tampilan waktu selesai:** Jika `completed_at` terisi, tampilkan dalam format Indonesia lengkap (`formatDateTimeId(task.completed_at)`).

## Input dan validasi
- Tidak ada input perubahan data pada modal detail (Read-Only).
- Pengguna Admin yang ingin mengubah tugas tetap memakai tombol **Ubah** di **Daftar Pekerjaan Unit**.

## Tampilan dan teks
- Judul dialog: **Detail Pekerjaan** (terbuka sebagai dialog modal saat judul tugas atau tombol **Detail** ditekan).
- Memuat: judul, deskripsi, pegawai pelaksana, kategori, tanggal mulai, tenggat waktu, tanggal selesai (jika ada), `StatusBadge` (termasuk lencana keterlambatan bila ada), catatan status, tombol **Buka Tautan** (`target="_blank" rel="noopener"`), serta bagian **Riwayat Perubahan** berurutan dari perubahan terbaru ke terlama.
- Di bagian **Riwayat Perubahan**, setiap baris log menampilkan label aksi, perubahan nilai (`old_value` ke `new_value`), catatan, nama pengubah, dan waktu (`WIB`).
