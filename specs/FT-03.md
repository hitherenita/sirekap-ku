# FT-03 Pencatatan & Pengelolaan Pekerjaan (Admin CRUD)

Sumber PRD: Bagian 4 (Hak Akses Admin), BL-01, BL-02, BL-03, BL-05, FT-03, AC-03, AC-04, AC-05, TC-01, TC-02, TC-03, Bagian 11 (`WorkTask` & `TaskAuditLog`), Bagian 12 (Tombol Uji Tautan)

## Tujuan
Admin dapat menambah, mengubah, dan menghapus data pekerjaan pegawai lengkap dengan validasi tautan dokumentasi, pencatatan tanggal selesai otomatis, serta pencatatan riwayat perubahan tanpa fitur unggah berkas fisik.

## Alur
1. Admin membuka menu **Daftar Pekerjaan**.
2. Admin menekan tombol **Tambah Pekerjaan** untuk membuka formulir tambah, atau menekan tombol **Ubah** pada salah satu baris pekerjaan untuk mengedit.
3. Admin mengisi atau memperbarui: Judul Pekerjaan, Deskripsi, Pegawai Pelaksana, Kategori, Tanggal Mulai, Tenggat Waktu, Status, Catatan Status, dan Link Dokumentasi (URL).
4. Jika Link Dokumentasi terisi, Admin dapat menekan tombol **Uji Tautan** untuk membukanya di tab baru guna memastikan tautan aktif sebelum disimpan.
5. Admin menekan **Simpan Pekerjaan**:
   - Sistem memvalidasi peran Admin (BL-01), kelengkapan kolom wajib, aturan tanggal (`due_date >= start_date`), dan aturan tautan URL (BL-02).
   - Jika valid, sistem menyimpan data pekerjaan, mengatur `completed_at` sesuai aturan BL-03, dan menambah catatan baru pada `TaskAuditLog` (BL-05).
6. Untuk menghapus data pekerjaan, Admin menekan tombol **Hapus** pada baris terkait, membaca dialog konfirmasi, lalu menekan **Ya, Hapus** sehingga data pekerjaan (beserta log terkait) dihapus dari daftar.

## Data
- `TASK_STATUS_LIST`
- `VALIDATION_CONFIG` (`titleMaxLength`, `allowedUrlProtocols`)
- `VALIDATION_MESSAGES` (`forbiddenAction`, `invalidUrl`, `completedUrlRequired`, `dueDateBeforeStart`)
- `AppStorageState.tasks` (`WorkTaskEntity[]`)
- `AppStorageState.auditLogs` (`TaskAuditLogEntity[]`)
- `AppStorageState.users` (`UserEntity[]`)
- `AppStorageState.categories` (`WorkCategoryEntity[]`)

## Aturan dan rumus
- **Otorisasi (BL-01):** Hanya `ADMIN` yang dapat menambah, mengubah, atau menghapus data pekerjaan; peran `PEGAWAI` dan `PIMPINAN` ditolak dengan status `403`.
- **Zero File Storage (BL-02):** Tidak ada input unggah berkas (`<input type="file">`). Bukti kerja hanya berupa URL.
- **Validasi URL & Wajib Selesai (BL-02):**
  - Jika `documentation_url` (setelah `trim`) tidak kosong, nilainya harus berupa URI valid dengan protokol `http:` atau `https:` serta memiliki hostname domain yang sah (mengandung titik atau `localhost`). Jika tidak sah, tolak dengan `VALIDATION_MESSAGES.invalidUrl`.
  - Jika `status === 'Selesai'`, `documentation_url` wajib diisi. Jika kosong, tolak dengan `VALIDATION_MESSAGES.completedUrlRequired`.
  - Untuk status selain `Selesai` (`Belum Dimulai`, `Dalam Proses`, `Ditunda`, `Dibatalkan`), `documentation_url` boleh kosong.
- **Manajemen `completed_at` (BL-03):**
  - Saat status berubah atau disimpan sebagai `Selesai`, jika belum ada nilai manual/sebelumnya, sistem mengisi `completed_at = current_timestamp`.
  - Jika status diubah dari `Selesai` ke status selain `Selesai`, `completed_at` di-reset menjadi `null`.
- **Pencatatan Riwayat (BL-05):**
  - Pembuatan baru mencatat 1 log `CREATED` (`new_value = status`).
  - Perubahan status mencatat log `STATUS_CHANGED` (`old_value`, `new_value`, `note`).
  - Perubahan `documentation_url` mencatat log `LINK_UPDATED` (`old_value`, `new_value`).
  - Perubahan atribut lain (judul, deskripsi, pegawai, kategori, tanggal) mencatat log `DETAILS_UPDATED`.
  - Log baru selalu ditambahkan tanpa menimpa log sebelumnya.
- **Daftar pilihan pegawai & kategori:** Menampilkan pegawai dan kategori yang berstatus `is_active === true` (termasuk akun Admin yang aktif sesuai Asumsi Bagian 12). Saat mengedit tugas lama yang pegawai/kategorinya sudah nonaktif, nilai lama tetap dipertahankan agar dapat dilihat.

## Input dan validasi
- **Judul Pekerjaan** (`name="title"`, wajib, maks. 200 karakter): tidak boleh kosong setelah `trim`. Contoh error: `"Masukkan judul pekerjaan maksimal 200 karakter (contoh: Rekap Laporan Bulanan)."`
- **Deskripsi** (`name="description"`, opsional): rincian atau keluaran yang diharapkan.
- **Pegawai Pelaksana** (`name="employee_id"`, wajib): harus memilih pegawai yang valid. Contoh error: `"Pilih pegawai pelaksana pekerjaan."`
- **Kategori Pekerjaan** (`name="category_id"`, wajib): harus memilih kategori yang valid. Contoh error: `"Pilih kategori pekerjaan."`
- **Tanggal Mulai** (`name="start_date"`, `type="date"`, wajib): format `YYYY-MM-DD`. Contoh error: `"Pilih tanggal mulai pekerjaan."`
- **Tenggat Waktu** (`name="due_date"`, `type="date"`, wajib): format `YYYY-MM-DD`, harus memenuhi `due_date >= start_date`. Jika lebih awal, tampilkan `VALIDATION_MESSAGES.dueDateBeforeStart`.
- **Status** (`name="status"`, wajib): salah satu dari `TASK_STATUS_LIST` (default `Belum Dimulai`).
- **Tanggal Selesai** (`name="completed_date"`, `type="date"`, opsional, tampil saat `status === 'Selesai'`): jika diisi, dicatat sebagai tanggal selesai aktual; jika dikosongkan, sistem otomatis mengisi waktu saat disimpan.
- **Catatan Status** (`name="status_note"`, opsional): alasan penundaan, pembatalan, atau keterangan progres.
- **Link Dokumentasi (URL)** (`name="documentation_url"`, `type="url"`, wajib jika `status === 'Selesai'`): harus diawali `http://` atau `https://`.

## Tampilan dan teks
- Judul bagian: **Daftar Pekerjaan Unit**
- Deskripsi singkat: **Catat, perbarui status, dan tautkan bukti dokumentasi pekerjaan pegawai.**
- Tombol aksi utama Admin: **Tambah Pekerjaan**
- Formulir Tambah dan Ubah pekerjaan terbuka dalam dialog modal di atas daftar pekerjaan.
- Di samping input URL pada formulir, sediakan tombol **Uji Tautan** (`target="_blank" rel="noopener"`) yang aktif ketika format URL valid.
- Saat **Hapus** ditekan, muncul dialog konfirmasi bertuliskan judul tugas dan tombol **Batal** serta **Ya, Hapus**.
- Untuk peran `PIMPINAN`, tombol **Tambah Pekerjaan**, **Ubah**, dan **Hapus** tidak ditampilkan.
